# 2026-11-12 起始讨论

和 Claude Code 的一次讨论，记录想法怎么来的、定了什么。原话不全录，只记结论和理由。

## 起点

我的想法：把工作区里的 Slack 收件队列（launchd 每 5 分钟拉未读，交给 agent 起草回复）扩展成一个通用的 personal agent bot。触发条件有很多种：Slack 消息、Jira 单、Notion 评论、GitHub issue。它是一个独立的桌面 app，不跑在终端里，也不跑在 Claude desktop 里，把任务交给本机的 agent CLI 去执行。在 app 里能看到它在处理哪些任务、每个任务的状态和详情，也能管理任务。

## 判断：能做，Slack 收件队列就是雏形

- **骨架本来就是通用的**：拉事件 → SQLite 账本 → 加锁拉起 agent 跑 skill → 状态机（失败三次标 failed）。Slack 专属的只有三处：采集、起草命令、skill。
- **已经跑出了量**：9 天 202 条，其中 85 条出了草稿。
- **路由表已经有了**：工作区里「可接管的工作」清单写的就是「什么触发 → 跑哪个 skill → 什么授权」，现在是文档，可以直接变成配置。

## 讨论中提出、写进方案的想法

- **profile 分离**：执行时把 cwd 设到 profile 所在的工作区，CLAUDE.md、skill、memory 就会自动加载。数据落在 profile 自己的 `.state/` 里。
- **一件事一个任务**：同一张单在 Jira、Slack、PR、部署里各冒一次。按关联键把这些事件挂到同一个任务上，详情页是一条跨源时间线。
- **事件能新建任务，也能唤醒任务**：任务可以停在「等待 X」，X 发生时 resume 原来的会话接着做。
- **审批卡**：agent 的权限请求和对外动作都变成 app 里的卡片，我点了才执行。
- **原地派活**：在 Slack 或 GitHub 上用一个约定的标记（emoji 或「稍后处理」）把东西派给它。

## 有过的顾虑

2026 年放弃过好几个 agent 工具。这次的不同在于：它是从一个已经天天在用的东西长出来的，不是从零造。
