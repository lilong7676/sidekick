# 项目上下文

> 状态：Phase 0 验证完成。名字 sidekick：搭档、小跟班。

## 要解决的问题

工作里每天有一批「别人找我」的事件，大部分要我先看一遍、查证据，再起草回复或者动手：

| 来源 | 量（2026-11 实测） |
|---|---|
| Slack：DM、@我、我参与的 thread 有新回复 | 9 天 202 条 |
| Jira：指派给我或我关注的单有更新 | 7 天 13 张 |
| GitHub：review 请求、评论、状态变化 | 未读通知 19 条 |

这些事里，流程固定的那部分已经沉淀成了 skill（工单闭环、Slack 值守等）。但触发它们的方式只有两种，都不好用：

- **我手动贴链接**：在终端或 Claude desktop 里一件件发起。
- **launchd 脚本**：现有的 Slack 收件队列。它只有 Slack 一个源，没有界面，跑完看不到过程，卡住了没法接手，也不能等某件事发生后再接着做。

## 要做的东西

一个本机常驻的 agent 调度器：

```
事件（Slack / Jira / GitHub / 我手动派） → 任务 → 交给 Claude Code CLI 执行
                                              ↓
                       菜单栏 app：看进度、批准对外动作、接管会话
```

和「再开一个聊天窗口」的区别在于三点：

- 任务进账本，不会丢。
- 任务能停下来等某件事，事件到了自动唤醒。
- 对外动作统一走审批，我点了才发。

## 用户

一期是我自己，用在工作上。

做好了要在公司推广，所以从一开始就把两层分开：

- **引擎**：本仓，不含任何个人或公司的信息。
- **profile**：放在使用者自己的工作区里，包括事件源、路由、skill、授权策略。

二期再加个人 profile，接我自己的 GitHub 仓库。

## 范围

一期做：

- **profile**：只做工作 profile，由现有的工作区提供。
- **runner**：只支持 Claude Code CLI（`claude -p`）。接口按 ACP 的形状设计，方便以后换。
- **事件源**：Slack（接替现有的收件队列）、GitHub、Jira、手动派活。
- **审批**：所有对外动作（发 Slack、评论 Jira 或 GitHub、流转、合并）都由我在 app 里点批准。
- **app**：Swift 菜单栏 app，包括任务列表、详情、日志流、审批、重试、取消、接管、手动派活。

## 不做

- 个人 profile：二期再做。
- 其他 runner（opencode、Codex）：等 ACP 接口稳定后再说。
- Notion 事件源：本机没有 CLI，要另配集成 token，放到后面。
- 云端运行、webhook：本机没有公网入口，所有事件源都靠轮询。
- 自动对外发送：不存在「免确认」档。
- 聊天式 UI：app 只做任务视角，要对话就接管到终端。
- 手机端审批：手机上只收提醒（Slack 发给我自己），审批回到电脑上做。
